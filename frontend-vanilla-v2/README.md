# 3D CRT Portfolio (plain HTML/CSS/JS)

A retro CRT TV rendered with Three.js. The Angular "Windows XP" portfolio
(`../../portfolio`) runs inside an iframe that the CSS3D renderer maps onto the
TV screen, so the desktop is fully interactive inside the 3D scene. The site
itself has no framework and no bundler: it is plain HTML, CSS and native ES
modules.

## Structure

```text
frontend-vanilla-v2/
├── index.html            # Page head, settings panel, screen element with the iframe, import map
├── css/style.css         # Layout, settings panel, screen size and CRT overlay effects
├── js/
│   ├── main.js           # Entry point: settings panel, intro timing, scene startup
│   └── scene/            # Three.js scene, one file per responsibility:
│       ├── index.js          # builds the scene + render loop (start reading here)
│       ├── renderers.js      # WebGL + CSS3D renderers, resize
│       ├── room.js           # background photo and lights
│       ├── dust.js           # floating dust (InstancedMesh)
│       ├── tv-model.js       # load the TV, fit the screen element onto it
│       ├── occlusion.js      # clip-path so the screen stays inside the bezel
│       └── camera-intro.js   # opening camera move
├── os/                   # Built Angular portfolio (generated by scripts/build-os.mjs)
├── scripts/
│   ├── build-os.mjs      # Builds the Angular app into os/
│   └── webpack.os.cjs    # Webpack override used by that build
├── assets/               # Room background and the settings panel font
├── basis/                # KTX2 (Basis) texture transcoder for the TV model
└── crt_tv_basis.glb      # TV model
```

## How the screen works

- The `#screen` element is 1024x768 CSS pixels; that is the viewport the
  portfolio sees inside the iframe (`window.innerWidth` is 1024 there).
- `scene/tv-model.js` places it on the TV screen mesh with a `CSS3DObject` and clips it
  with a `clip-path` traced from the curved screen mesh (`scene/occlusion.js`), so it never pokes out
  of the bezel.
- The CSS3D layer sits above the WebGL canvas. Only the screen element takes
  pointer events, so mouse and keyboard go straight into the iframe.
- The camera starts close on the screen and pulls back once the iframe has
  loaded (`INTRO_HOLD_MS` in `main.js`).

## Building the portfolio into `os/`

Requires the Angular workspace with its dependencies installed
(`npm install` in `../../portfolio`). Then, from this folder:

```bash
node scripts/build-os.mjs
```

The script builds the app with base href `/os/`, without the service worker,
copies the output into `os/` and rewrites the app's root-absolute `/assets/...`
paths to `/os/assets/...`. Set `PORTFOLIO_DIR` if the workspace lives
elsewhere.

The portfolio's own `webpack.config.js` inlines the whole build environment
(`PATH`, `HOME`, `npm_config_*`, ...) into the bundle, so the build uses
`scripts/webpack.os.cjs` instead, which only exposes `SERVICE_KEY`,
`TEMPLATE_KEY` and `PUBLIC_KEY`. Set those (EmailJS) before building or the
"Get in touch" form cannot send messages.

## Run locally

Serve the folder over `http://`; opening `index.html` from disk does not work:

```bash
npx serve .
```

Then open <http://localhost:3000> (or whatever port the server prints).

## Deploy

Run the build script, then upload this folder, including `os/`, to any
static host, served from the domain root. The iframe loads `/os/`.
